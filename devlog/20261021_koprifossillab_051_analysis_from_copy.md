# koprifossillab 051 — 분포 분석을 PBDB 사본에서: 한도 없이, 지도와 같은 좌표로

2026-10-21 · `feature/pbdb-occurrence-copy`

[P01](20261020_koprifossillab_P01_analysis_rigor.md) 의 나3·나4·나5. 연구자가 정한 것: **분석만 사본**, 지도의 찾기 점·팝업은 실시간 PBDB(P01 §11.4).

## 1. 무엇이 바뀌나

`fetchSeries`(분류군 A·비교 분류군 B 의 시간 계열)가 PBDB `occs/list`(5,000 건 한도) 대신 **사본의 조각**(050)을 먼저 본다.

1. 이름표(첫 글자 파일)에서 이름 → 채택 분류군의 `[lft, rgt]`. 같은 이름이 여럿이면(동명, tupandactyl 026) 고른 번호, 아니면 산출이 가장 많은 것
2. 산출이 50,000 건 이하 — 구간에 걸친 조각만 받아 산출 하나하나를 센다. 나라·지층은 산지 칸으로 거른다(PBDB 질의의 `cc`·`formation` 과 같게)
3. 50,000 건 초과 — 파이프라인의 **요약**(시점 수·몫·몬테카를로·고위도 분위). 나라·지층을 걸었으면 요약을 쓸 수 없어 PBDB 절 단위 수로 돌아간다
4. 사본에 없는 이름(사본 뒤에 생긴 것) — 지금처럼 PBDB 에 바로

그래서

- **한도가 5,000 → 50,000 건**으로 — 그 사이의 분류군(과·목 다수)이 퇴적기원·연대 범위·품질 거르기를 따르고, 시점 몫·몬테카를로가 붙는다
- **고위도 곡선이 지도와 같은 틀**(②) — 산출의 위도는 그 산지를 그 시점 나이로 v19o 로 돌린 것(조각의 시점 좌표). 최근 절 시점은 그 절이 쓰는 0·5 Ma
  지도의 좌표. 곡선 밑의 좌표 틀 문구도 "지도의 점과 같다" 로 바뀐다(043 의 "PBDB 고좌표 … 1–2° 다를 수 있다" 는 사본이 없을 때만)
- 큰 분류군의 고위도 곡선을 "시점마다 산지로 그리기"(PBDB 에 110 번 묻기, 1~2 분) 없이 요약으로 바로 그린다
- 분석 패널 밑에 "분포 분석: PBDB 사본(날짜 받음) — 지도의 찾기 점과 팝업은 PBDB 에 바로 묻는다"

다양성 곡선(절마다 속 수)은 그대로 PBDB `occs/diversity` 다 — 범위 통과 속 수(Foote) 같은 절 단위 셈을 사본에서 다시 하는 것은 이 단계에 넣지 않았다.

## 2. 확인

로컬(10-21 사본, 조각을 구운 index.json)에서:

- **Trilobita**(49,031 건 — 전에는 5,000 건을 넘어 PBDB 절 단위 수) — 이제 사본에서 하나하나 센다. 조각 9 개를 받는다. 500 Ma: 산출 2,646 · 몫 1,611.6 ·
  몬테카를로 95% 1,494–1,766. 고위도 곡선 밑이 "지도의 점과 같다 — … v19o … (PBDB 사본)"
- **Bivalvia**(164,311 건) — 요약. 100 Ma: 산출 6,957 · 몫 2,481.0 · 95% 2,261–2,771. 고위도 곡선이 요약의 분위로 그려진다
- **Tyrannosaurus** 70 Ma 재현 묶음 — 일곱 파일(README·manifest·query·localities·series·**occurrences**·**references**). 산출 85 건마다 이 지도에서의
  몫·고위도·동정 표지·문헌 번호, 문헌 목록, manifest 의 `pbdb_copy.snapshot` = `20261021-16b95ba3245f`

## 3. 재현 묶음의 온전한 판(나6)

분포를 사본에서 셌으면 묶음에 **센 산출 하나하나**(`occurrences.csv`)와 **그 문헌**(`references.csv`, 조각 `occs/refs`)이 들고, manifest 에
사본의 표마다 sha256 이 든다. 주간 백업이 그 주의 사본을 지우지 않으므로(docs/백업.md) 같은 수를 다시 얻을 수 있다 — README 의 "재현의 한계" 를
그에 맞게 고쳤다. 지도의 찾기 점과 다양성 곡선은 여전히 실시간 PBDB 라 그 한계는 남는다.

P01 §8 의 `python -m pipeline reproduce <묶음.zip>`(옛 사본으로 다시 세는 명령)은 하지 않았다 — 묶음의 `occurrences.csv` 가 센 산출을 모두 담고 있어,
다시 세는 데 사본이 꼭 필요하지 않다.

## 4. 버린 것

- **다양성 곡선을 사본에서** — 범위 통과·절 안 산출 속 수는 PBDB 의 절 단위 셈(Foote)이다. 사본으로 다시 하려면 절 단위 몫과 속의 첫·끝 출현을
  새로 정의해야 한다. 지금은 곡선 밑에 "PBDB occs/diversity" 라 적는다(043)
- **찾기 점까지 사본으로** — 연구자가 지도는 실시간으로 두기로 했다
