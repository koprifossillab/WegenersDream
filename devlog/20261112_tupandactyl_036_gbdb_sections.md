# tupandactyl 036 — GBDB 단면의 채집을 PBDB 곁에 따로 올리고, 겹침을 표시한다

2026-11-12 · `feature/gbdb`

연구자(11-12)가 GBDB(geobiodiversity.com)의 자료도 PBDB 와 통합할 수 있는지 물었고, 조사 뒤 권한 순서(사본 조건 확인 → 겹침 세기 →
따로 된 층 → 겹침을 뺀 셈)대로 하자고 했다. 같은 날 고지형 등고선을 연구방법론 창에서 겹쳐 보기로 옮기고, 지표 기온 설명에서 전 지구 평균을 뺐다.

## 1. 원본 — 사이트가 아니라 Zenodo 사본

- GBDB 사이트는 화면용 API(`/api/search/fossilOccurrence` 등)에 로그인 없이 답한다. 그러나 **문서가 없고 이용 조건도 적혀 있지 않다** —
  62 만 건을 긁으면 상대 서버에 짐이고, 조건을 모르는 자료를 공개 사이트에 다시 내놓을 수 없다
- ESSD 현황 논문(Xu et al. 2020)이 가리키는 **Zenodo 4245604**(2020-11 정적 사본)는 **CC BY 4.0** 이다. 이것을 PaleoDEM 처럼 SHA-256 으로
  고정했다(`sources/gbdb.json`). 최신 자료가 아닌 대신 재현되고 조건이 분명하다
- 사본은 엑셀 둘이다. 화석 시트(`GBDB_fossils.xlsx`, 42 만 행)에는 나이가 없어 **단면 시트**(`GBDB_all sections.xlsx`, 76 만 행 —
  단면 × 층 단위 × 채집 × 산출)만 쓴다
- **엑셀 읽개는 표준 라이브러리로**(`pipeline/xlsx.py`) — openpyxl 을 들이지 않으려고. 시트 XML 이 1 GB 라 `iterparse` 로 흘려 읽고, 1 분 남짓

## 2. 무엇이 남나

| | 수 |
|---|---|
| 화석 행 | 573,982 |
| 층 단위에 나이가 없어 뺀 것 | 326,266 (57 %) |
| 나이·좌표가 있는 산출 | 247,655 |
| 채집(단면·층 단위·채집 번호) | 44,816 |
| 단면 | 5,627 (중국 94 %) |

나이 없는 행이 많은 것은 사본의 성격이다 — 층 단위에 시대 이름조차 없다. 지층 이름으로 나이를 메우는 것은 짐작이라 하지 않았다.

## 3. PBDB 와 겹침 — 같은 기록을 두 번 세지 않게

- **규칙**: 채집에서 10 km 안, 연대가 겹치는(여유 ±1 Myr) PBDB 산지 가운데 이 채집 속의 **절반 이상**을 가진 것이 있으면 겹친 것으로 보고 그
  산지 번호를 `dup` 에 적는다. PBDB 쪽은 주간 산출 사본의 조각(`occs/chunk`, koprifossillab 050)에서 읽는다 — 사본이 없으면 겹침을 안 센다
- 결과: **4,767 / 44,816 채집(10.6 %)**. 속 단위로 보면 GBDB 산출의 약 15 % 가 가까운 같은 시대 PBDB 산지에 있다. 즉 GBDB 의 대부분은 PBDB 에 없는 자료다
- 버린 것: **좌표만으로 겹침** — 중국의 유명 단면(메이산 등)에는 PBDB 산지가 여럿 있고 같은 자리 다른 층이다. **문헌으로 겹침** — 두 DB 의
  문헌 표기가 달라(중국어 학술지의 영문 표제·저자 표기) 맞추기 어렵다. 속의 일치가 가장 덜 틀린다. 동물이명·다른 동정은 놓친다(설명에 적었다)

## 4. 지도 — 따로 된 층

- 화석 산지 절의 "GBDB 단면의 채집도 보기". **네모**로 그려 PBDB 의 원·세모와 섞이지 않게 하고, 겹친 채집은 **속 빈 네모**다. 색은 보라(`--gbdb`) —
  해양 노랑·육상 빨강·찾기 초록과 다르다. "시대(기)" 색이면 기의 색
- 좌표는 오늘날 좌표를 시점 나이로 **v19o 로 돌린 것**이다(CLAUDE.md "판 모델을 하나로"). GBDB 화면의 "ancient" 좌표는 판 모델을 밝히지 않아 버렸다
- 누르면 단면 파일(`gbdb/sections/<번호 % 100>.json`)을 읽어 채집의 산출·문헌과 **단면의 층 차례**(위가 젊다)를 보인다 — PBDB 에 없는 정보가 이것이다.
  층의 위아래는 나이로 정렬하고, 같은 나이면 시트의 차례를 거꾸로(시트는 아래에서 위로 적는다)
- **찾기·종합 보기·나라·지층 거르기 중에는 쉰다** — GBDB 에는 PBDB 의 분류 체계·퇴적 환경·국가 코드가 없다. 분류군 찾기에 GBDB 를 더하려면 속 이름을
  PBDB 분류에 맞추는 표가 먼저다(다음 일)
- 지구본에는 아직 안 오른다(지구본은 PBDB 점 층만 비춘다)

## 5. 셈에 더하기 — 표본 노력만

- 연구방법론 창 "분포 표면" 에 "표본 노력에 GBDB 채집 더하기" — 겹친 채집을 뺀 나머지의 시점 몫을 칸에 더한다. 표본 노력은 "어디를 찾아봤나" 라
  분류군과 상관없이 더할 수 있다
- 점유(찾은 분류군)·다양성에는 아직 안 더한다 — 위의 분류 체계 문제. 표본 노력에만 더하면 "중국에 표본이 있는데 이 분류군이 없다" 를 읽을 수 있다

## 6. 같은 날의 화면 정리

- **고지형 등고선을 겹쳐 보기로** — 연구자: 방법론이 아니라 겹쳐 보는 층이다. 셈과 상관없으니 Casual 에서도 보인다. 고른 것은 `wegener.contour` 에
  따로 기억한다(035 의 연구방법론 창 저장값은 버린다 — 하루 쓴 값이다). 설명(⚙)의 "고지형" 묶음은 지우고 주의(해안선 층과 다른 자료)는 아래 글에 옮겼다
- **지표 기온 설명에서 전 지구 평균을 뺐다** — 온도계(wetherilli 002)가 같은 값을 보인다. PaleoClim 의 "온도계를 비운다" 도 뺐다
