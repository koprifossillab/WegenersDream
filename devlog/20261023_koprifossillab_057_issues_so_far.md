### 1.1 운영 자료가 10-04 에 멈춰 있다 — 새 분석 기능이 운영에서 꺼져 있다

- **무엇**: 운영 이미지는 v1.12.0(10-21)인데 `/healthz` 가 `degraded` — 자료가 10-04 의 것이다. 1.4.0 부터의 기능은 `index.json` 의 새 칸(`rules.analysis`·
  `rules.quality`·`occurrences`)을 써서, 다시 가공하기 전에는 숨는다
- **왜**: 10-05·10-12·10-19 주간 갱신이 모두 운영 반영(rsync)에서 멈췄다. jschoi 가 손으로 만든 `/srv/WegenersDream/data/taxa_ko` 의 시각·권한을
  paleoadmin 이 못 바꿔 `rsync -a` 가 코드 23 으로 끝났고, 스크립트는 `index.json` 을 옮기기 전에 멈췄다(052)
- **고친 것**: 운영 반영을 `rsync -rlt`(권한·소유자를 맞추지 않는다)로 — 1.9.1(#59)
- **남은 것**: paleoadmin 으로 `taxa_ko` 를 옆으로 옮기고(`mv /srv/WegenersDream/data/taxa_ko /srv/WegenersDream/data/taxa_ko.jschoi-20261021`)
  `deploy/host/weekly_refresh.sh` 를 한 번 돌려야 한다. 그대로 두면 10-26 02:30 cron 도 같은 자리에서 멈춘다 — cron 이 도는 스크립트는 main 을
  당기기 **전**의 판(`rsync -a`)이라 #59 의 고침이 그 실행에는 들지 않는다
- **알게 된 것**: 갱신 실패가 세 주 동안 아무에게도 닿지 않았다 — `/healthz` 의 `degraded` 를 보는 사람이 없었다(TODOs "주간 갱신 실패를 알린다")

### 1.2 paleoadmin 으로 SSH 접속이 안 된다

- **무엇**: 자료 갱신은 paleoadmin 만 할 수 있다 — PBDB 원본이 `mkstemp` 로 생겨 권한 600 이라 jschoi 는 못 읽는다. 연구자가 jschoi 의 공개 열쇠
  (`SHA256:O+W0SUB56jVpjFO0/faMhWj9qX4fQ0YFX/0XB26tmlY`)를 paleoadmin 의 `authorized_keys` 에 넣었다고 했지만 서버가 두 번 다 거절했다
- **확인한 것**: 내 쪽은 맞는 열쇠를 내민다(`ssh -v`: "Offering public key … O+W0SUB56…"). 서버의 sshd 설정에 AllowUsers 같은 제한은 없다.
  paleoadmin 의 `~/.ssh` 시각은 10-07 그대로 — 새 파일을 만들지 않았다. 인증 로그는 jschoi 로 못 본다
- **가장 그럴듯한 원인**: `authorized_keys` 의 권한(paleoadmin 은 umask 002 라 664 로 생기면 sshd 가 무시한다) 또는 열쇠 줄이 들어가지 않았거나 끊김
- **할 일(paleoadmin 으로)**: `chmod 700 ~/.ssh`, `chmod 600 ~/.ssh/authorized_keys`, `ssh-keygen -lf ~/.ssh/authorized_keys` 로 `O+W0SUB56` 줄이
  있는지 본다. 없으면 열쇠 줄을 한 줄로 더한다
