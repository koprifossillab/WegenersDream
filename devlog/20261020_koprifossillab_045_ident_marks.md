# koprifossillab 045 — 동정 표지와 동정 거르기: cf.·aff.·?·속 미동정

2026-10-20 · `feature/ident-marks`

[P01](20261020_koprifossillab_P01_analysis_rigor.md) 의 가3. 연구자가 정한 것: **모두 보이고 표시만**, 빼는 것은 고를 때만(P01 §11.1).

## 1. 무엇이 빠져 있었나

찾기·팝업의 산출 목록은 PBDB 의 **채택명**(`accepted_name`)만 적었다 — "cf. Tyrannosaurus rex" 도 "Tyrannosaurus rex" 로 보였다. 찾기
커서 목록은 원 동정명을 괄호에 적어 글자로는 보였지만, 셀 때는 가르지 않았다. PBDB 전체에서 cf.·aff.·? 등 불확실한 동정이 11.8%, 과
이상까지만 동정된 것이 6.8% 다(P01 §1).

## 2. 규칙 — `pipeline/quality.py` 한 곳

PBDB 는 `show=ident` 로 수식어 칸(`primary_reso`·`subgenus_reso`·`species_reso`)을 준다(값이 있을 때만 칸이 온다, 10-20 확인).
글자(`identified_name`)를 뜯지 않는다 — "n. gen."·"informal" 따위에서 틀린다.

| 표지 | 뜻 |
|---|---|
| g 속 불확실 | 속·아속 수식어가 cf.·aff.·?·따옴표·informal |
| s 종 불확실 | 종 수식어가 그것과 ex gr. |
| h 속 미동정 | `identified_rank` 가 속보다 위 |
| n 새 이름 | n. gen.·n. sp. 등 — 불확실이 아니라 처음 기재된 기록의 표시 |

`QUALITY` 가 `index.json` 의 `rules.quality` 로 가고 셈은 `analysis.js` 의 `identMarks`. 044 처럼 두 시험이 같은 보기 파일
(`pipeline/tests/quality_cases.json`)을 읽는다. JS 시험은 규칙도 그 파일에서 읽어야 해서(파이썬 dict 를 node 가 못 읽는다) 파일에 `rules` 를
함께 두고, **파이썬 시험이 그것이 `QUALITY` 와 같은지 본다** — 규칙이 두 곳에 적혀도 어긋나면 CI 가 멈춘다.

`flags` 칸(I·F)은 뜻을 PBDB 문서로 확인하기 전까지 쓰지 않는다.

## 3. 화면 — 분석 엄밀 표기(043)를 켰을 때

- **표지**: 찾기의 커서 목록, 산지 팝업의 산출 목록, 종합 보기의 산지 목록에서 이름 옆에 "속 cf." · "종 aff." · "속 미동정" · "새 이름"
  (주의 글씨 색). 질의 셋에 `show=ident` 를 더했다 — 행마다 몇십 바이트
- **거르기**(기본 끔, 기억하지 않는다): 분류군 찾기 절의 "속이 불확실한 산출 빼기"·"속까지 동정 안 된 산출 빼기". 지도의 점(산지에 남은 산출이
  없으면 그리지 않는다)·상태 줄의 산지·산출 수·시점 몫·커서 목록, 그리고 산출을 하나하나 센 분류군(5,000 건 이하)의 분포·고위도·몬테카를로가
  따른다. 상태 줄에 "동정 거르기로 뺀 산출 N건"

확인: Tyrannosaurus 70 Ma 산출 85 건 → 속 불확실을 빼면 73 건(12 건 = cf. 8 + ? 4 — P01 §10.1 에서 PBDB 로 센 수와 같다).

## 4. 버린 것·남은 것

- **종 불확실로 거르기** — 속 단위 분석(다양성은 속)에는 종 수식어가 속의 존재를 흔들지 않는다. 표지만 단다
- 5,000 건이 넘는 분류군의 분포는 PBDB 절 단위 수라 거르기가 들지 않는다 — 산출 단위 사본(P01 나5) 뒤
- 다양성 곡선(PBDB `occs/diversity`)에도 들지 않는다 — PBDB 에 그런 거르기가 없다. 043 의 "세는 규칙" 문구에 이미 "거르기가 들지 않는다" 가 있다
