# koprifossillab 050 — 산출 사본을 분류 나무 순서의 정적 조각으로 굽는다

2026-10-21 · `feature/pbdb-occurrence-copy`

[P01](20261020_koprifossillab_P01_analysis_rigor.md) 의 나2(§3.2). 연구자: 정적 공개판을 지킨다, 큰 분류군 문턱 50,000 건(P01 §11.4).

## 1. 꼴 — `pipeline/occurrences.py`, `data/derived/occs/`

| 파일 | 담는 것 |
|---|---|
| `occs/index.json` | 사본의 받은 날·`snapshot`·표마다 sha256, 조각 목록(`file`·`lft_lo`·`lft_hi`·`n`), 이름표·요약·문헌 조각의 자리, 셈 |
| `occs/chunk/NNNN.json` | 산출 행(번호·산지·채택 분류군·`lft`·이름·계급·속·원 동정명·동정 표지·문헌 번호) + 그 조각의 산지 칸(연대·환경·국가·지층·`precise`·고유 산지-시간 열쇠·**시점마다의 v19o 좌표**) |
| `occs/taxa/<첫 글자>.json` | 이름(동의어 포함) → [채택 번호, `lft`, `rgt`, 계급, 사본의 산출 수, 채택 이름] — 동명은 여럿 |
| `occs/summary/<번호>.json` | 산출 50,000 건 넘는 분류군의 시점마다 수 |
| `occs/refs/<번호÷1000>.json` | 사본의 산출이 쓰는 문헌(형식 갖춘 글·DOI) — 재현 묶음(051) |

**산출을 채택 분류군의 `lft` 순으로 늘어놓으면 어떤 분류군이든 그 아래의 산출이 `[lft, rgt]` 의 한 구간이다.** 그 순서로 1 MB 남짓씩
자르고 조각마다 `lft` 의 처음·끝을 적어, 브라우저는 구간에 걸친 조각만 받는다. 시험(`OccurrenceChunkTest`)이 조각이 빈틈·겹침 없이 모든 산출을
나무 순서로 담는지, 분류군의 산출 수가 구간 길이와 같은지 본다.

산지의 시점 좌표는 `fossils.build` 가 시점 파일을 쓰며 함께 모은다(`keep`) — 같은 회전을 두 번 하지 않는다.

## 2. 굽어 보니(10-21 사본)

| | |
|---|---|
| 산출 | 1,782,622 |
| 지도에 오르지 않는 산지의 산출 | 382,606 — 뺀다(지도와 같은 산지 집합, 016) |
| 나무에 자리가 없는 분류군 | 42,331 — 뺀다(채택 번호가 없는 비공식 이름 등) |
| **쓰는 산출** | **1,357,685** |
| 조각 | 232 개(하나 1.2 MB 안팎, 5,800 건 남짓) |
| 요약(50,000 건 초과) | 74 분류군 — Animalia 부터 Scrotifera 까지 |
| 문헌 조각 | 97 개, 12 MB |
| 모두 | 297 MB(압축 전). 굽는 데 2 분 남짓 |

뺀 산출이 많다(21%) — PBDB 고좌표가 없는 산지(46,930 곳)에 산출이 몰려 있다. 지도에 없는 산지를 분석에만 넣으면 지도의 점과 분석의 수가
다른 산지 집합이 되어 뺐다. 그 산지를 넣을지는 016 의 규칙과 함께 연구자가 정한다(PBDB_자료_처리 §6).

## 3. 큰 분류군의 요약

시점마다 산출 수(겹침)·시점 몫·몬테카를로 95%(산지 단위, 200 번, 고정 씨앗 — numpy)·속 수의 기대값(Σ 1 − Π(1 − w))·고위도 분위(시점 좌표,
몫 가중). 0~540 Ma 의 5 Myr 시점만이다 — 최근 절 시점(tupandactyl 009)은 뷰어에서 정해지는 창이라 요약에 없다. 거르기는 들지 않는다.
